# 0.7.23 — Cache performans kabul paketi

Bu sürüm `defineCachedResource` için memory-first doğruluk kapısını, gerçek Redis ile çalışan dağıtık
regresyon matrisini ve identity/gzip olarak ayrılmış kapasite profillerini ekler.

`origin-migrate --apply`, mevcut kapasite paketi bulunan uygulamalara iki additive runner dosyasını,
kısa kullanım dokümanını ve şu script'leri ekler:

- `cache:acceptance`
- `cache:acceptance:redis`
- `capacity:gzip`
- `performance:gate`

Migration mevcut `load-test/capacity.mjs` dosyasını overwrite etmez. Yeni template'te capacity runner
doğruluk matrisini kendi içinde release kapısı olarak çalıştırır; eski projelerde `performance:gate`
aynı sıralamayı iki komutla garanti eder.

Redis opsiyoneldir. Memory gate Redis bağlantısı açmaz. Redis matrisi yalnız açıkça
`REDIS_URL=... pnpm cache:acceptance:redis` ile çağrıldığında çalışır ve uygulama kaynak kodunda backend
dalı gerektirmez.

## Review kapanışı (OR)

Bu sürüm, cache performans paketiyle aynı release candidate üzerinde test edilen platform
düzeltmelerini de taşır (bkz. CACHE_PERFORMANCE_ROADMAP.md § OR):

- **Migration sonucu artık üç durumu ayırır**: `patched`, `already-applied`, `manual-required`.
  `server/product/boundary-pages.tsx` bilinen generated kalıba uymuyorsa (custom dosya) migration onu
  regex ile değiştirmeye çalışmaz; `origin-migrate` çıktısında "Elle müdahale gerekiyor" olarak
  raporlar ve migration'ı uygulanmış saymaz — `origin:doctor --strict` pending göstermeye devam eder.
  Bu durumda `RouteErrorPage` bileşenini elle `errorId` prop'unu (`RouteErrorBoundaryProps`) alacak ve
  PII-free bir referans gösterecek şekilde güncelleyin.
- **Island hata gösterimi artık SSR içeriğini silmiyor.** `createIslandMounter` yeni bir
  `formatIslandError({ island, errorId, error }) => string` seçeneği alır; verilmezse platformun
  nötr İngilizce varsayılanı kullanılır. Kendi kopyanızı/dilinizi göstermek istiyorsanız
  `src/hydrate.client.tsx` içine ekleyin:

  ```ts
  export const mount = createIslandMounter({
    modules: import.meta.glob<IslandModule>("./islands/*.tsx"),
    formatIslandError: ({ errorId }) => `Bir sorun oluştu. Referans: ${errorId}`,
  });
  ```

  Gerçek post-mount component failure'ları için opsiyonel `onComponentFailure(element, context)`
  kancası eklenebilir. Platform bu durumda zaten kendi nötr durum elemanını (`role="alert"`,
  `formatIslandError`'dan gelen metin) island kökünün yanına ekler — `onComponentFailure` bunun
  _yerine_ geçmez, ona _ek_ bir kanca'dır; kendi fallback UI'ınızı `element`'in içine/yanına
  eklerseniz platformun durum elemanıyla yan yana görünebileceğini unutmayın.

- **`x-request-id` artık tek noktadan yazılıyor** (Hono sınırındaki `requestId` middleware'i); uygulama
  kodunda ayrıca set etmenize gerek yoktur, standalone `handle()`/`handleHead()` kendi garantisini
  korur.
- **`origin-scaffold-gateway`** artık değeri eksik bırakılan bir CLI flag'inde (`--cwd`, `--id`,
  `--fixture` vb.) seçenek adını içeren bir hata verir ve fixture/stdin girdisini 5 MiB ile sınırlar.
- **Production placeholder kontrolü** artık `CHANGE_ME`/`REPLACE_ME` gibi alt çizgili varyantları da
  exact-match olarak reddeder; normal release ID'lerdeki sıradan `todo` alt dizeleri hâlâ kabul edilir.
