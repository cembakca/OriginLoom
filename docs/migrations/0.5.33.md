# 0.5.33: gateway transport ve teslimat sıcak-yol optimizasyonları

Tür: geriye uyumlu runtime/template performans iyileştirmesi.

## Platform değişiklikleri

- Gateway fetch process başına keep-alive Undici dispatcher kullanır;
  `GATEWAY_MAX_CONNECTIONS` limiti origin başına uygulanır.
- Connect/header/body timeout'ları ayrı yapılandırılabilir; mutlak `GATEWAY_TIMEOUT_MS` korunur.
- Request-scoped parsed value deduplication için `memoizeRequestValue` eklendi.
- Başarılı access log'ları deterministic sampling destekler; hata cevapları sampling dışıdır.
- Histogram hot path tek bucket günceller, cumulative Prometheus serisi scrape sırasında üretilir.
- Static server precompressed Brotli/gzip asset varyantlarını negotiate eder.
- Runtime tarafından sıkıştırılan cevaplar cache doğruluğu için `Vary: Accept-Encoding` taşır.
- `origin-build` sıkıştırılabilir hash'li client asset'ler için `.br` ve `.gz` üretir.

## Mevcut generated proje

Paketleri `0.5.33` sürümüne yükseltin. Graceful shutdown içinde cache/instrumentation kapanışlarının
yanına şunu ekleyin:

```ts
import { closeGatewayTransport } from "@originloom/core/gateway-transport";

await closeGatewayTransport();
```

Bu çağrı gateway kullanabilecek revalidation, analytics ve worker drain işlemlerinden **sonra**;
cache/instrumentation kapanışından önce yapılmalıdır. Aksi halde drain sırasında başlayan yeni gateway
çağrıları kapanmış dispatcher'a denk gelebilir. Yeni template ayrıca `.env.production` ve deployment
ConfigMap'e gateway pool, log sampling ve compression değişkenlerini açıkça ekler.

`origin-build` kullanılıyorsa precompression otomatik devreye girer. Özel build script'i olan eski
projeler `origin-build`e dönmeli veya `dist/client/assets` için eşdeğer `.br/.gz` üretmelidir.

`performance:accept`, yeni raporlarda cache deneyleri ve hard budget sonuçlarını zorunlu tutar. Eski
veya eksik raporu doğrudan baseline yapmak yerine güncel template ile yeni bir full kapasite raporu
üretin.
