# 0.7.0: React tek renderer, mutation deseni

> **Not (0.7.2):** bu sürümde tanıtılan opsiyonel i18n eklentisi değerlendirildi ve kaldırıldı.
> Nedeni ve öğrenilenler: [ekosistem backlog'u](../ecosystem-backlog.md).

Tür: bir kırıcı değişiklik (vanilla renderer kaldırıldı) ve iki yeni template özelliği.

## Vanilla renderer kaldırıldı

`@originloom/vanilla` artık yayınlanmıyor; `pnpm create-app --vanilla` / `--renderer` bayrakları yok.
Sabit grup dört pakete indi: `shared`, `core`, `react`, `tooling`.

Sebep: kontratı doğruluyordu ama kullanıcısı yoktu. Buna karşılık her template değişikliğinin iki kez
yazılmasını, her release provasının iki kez koşmasını gerektiriyordu — ve fark edilmeden bozulabildiği
de görüldü (ürettiği uygulama bir süredir kendi `tsc`'sinden geçmiyordu).

Render kontratı (`OriginRenderer`) yerinde duruyor: `core` hâlâ hiçbir UI framework'ü bilmiyor ve
ikinci bir adaptör yazmak yalnız o kontratı implement etmekten ibaret.

**Vanilla bir projeniz varsa:** otomatik migration yoktur — HTML template'li sayfaları React
bileşenlerine çeviren bir dönüşüm mümkün değil. `origin-migrate` bu durumu tespit edip elle taşıma
gerektiğini bildirir. React'e taşıyana kadar 0.6.x sürümünde kalın.

## Mutation deseni template'e girdi

Üretilen uygulama artık çalışan bir yazma akışı taşıyor: `/contact` sayfasındaki form →
`POST /api/enquiries` → `server/api/enquiries.ts` → `server/services/enquiries.ts`.

- Same-origin guard + rate limit (`guardPublicApi`) handler'ın ilk satırında.
- Alan alan doğrulama, uzunluk sınırlarıyla.
- Post/Redirect/Get: tarayıcıya `303`, yenilemek formu tekrar göndermez.
- Sonuç sayfası `strategy: "never"` — bir ziyaretçinin sonucu diğerine servis edilemez.
- JavaScript kapalıyken çalışır; `e2e/ssr.no-js.spec.ts` bunu doğrular.

Rehber `docs/mutations.md`, skill `.claude/skills/mutations/`. Mevcut projeler için zorunlu bir adım
yok; yeni yazma uçlarında bu deseni örnek alın.

## i18n opsiyonel eklenti olarak eklendi

```bash
pnpm create-app shop-web --i18n              # tr, en
pnpm create-app shop-web --locales en,de,fr  # ilki varsayılan dil
```

Bayrak verilmezse üretilen uygulamada i18n'e ait **tek satır yoktur** (dosya, import, skill, doküman
dahil). Verilirse:

- Varsayılan dil öneksiz (`/catalog`), diğerleri önekli (`/en/catalog`); varsayılan dilin öneki
  `308` ile öneksiz adrese toplanır. Yani ikinci dili eklemek mevcut hiçbir URL'i taşımaz.
- `Accept-Language` yönlendirmesi bilinçli olarak yok: canonical URL'in ziyaretçiye göre farklı
  cevap vermesi hem cache'i hem index'i bozar.
- Locale kararı middleware `values`'ı ile yayımlanır, dolayısıyla paylaşımlı HTML cache key'ini
  otomatik böler.
- `<html lang>` istek başına çözülür; her sayfa tüm diller + `x-default` içeren hreflang kümesi
  taşır; sitemap her dili ayrı listeler.

Kullanım ve **kaldırma** adımları `docs/i18n.md` içinde.

### Platform tarafındaki karşılığı

- `PageMetadata.languageAlternates` ve `ResolvedMetadata.languageAlternates` eklendi; React head
  render'ı bunları `<link rel="alternate" hreflang>` olarak basar.
- `DocumentShell.htmlLang` artık `string | ((ctx) => string)`. Mevcut string kullanımları çalışmaya
  devam eder.

## Yükseltme

```bash
pnpm update "@originloom/*" --latest
pnpm origin:migrate --apply
pnpm install
pnpm ci
```

React kullanan mevcut projeler için davranış değişikliği yoktur.
