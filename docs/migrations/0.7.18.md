# 0.7.18 — Telemetry güvenilirliği ve geliştirme akışı

## Özet

- `market-stream` client telemetry kontratının server allowlist'ine eklendi.
- Fatal island hataları kullanıcıya PII'siz `client-…` support referansı gösterir.
- Route error boundary de hata verirse global SSR hata sayfası güvenli biçimde devreye girer.
- Client runtime JSON loglarında `pageRequestId` top-level sabit alandır; korelasyon yoksa `null`.
- `pnpm dev`, media config ile görsel/font kaynaklarını izleyip OG, favicon ve responsive çıktıları
  otomatik yeniler.
- 0.7.17'deki manuel SVGR, client entry ve Vite config hizalamaları otomatik migration oldu.

## Otomatik (`origin-migrate`)

| Migration id                           | Ne yapar                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `0.7.18-dev-experience-source-patches` | Bilinen eski `.svgrrc.cjs`, `src/entry.client.tsx` ve `vite.config.ts` kalıplarını güvenli ve idempotent biçimde günceller |
| `0.7.18-generation-aware-dev-reload`   | Bilinen `shouldReload` path allowlist'ini `/readyz` process generation koordinasyonunu açan `reload: {}` ayarına taşır     |

Migration yalnız tanıdığı generated kalıpları değiştirir; uygulamaya özel veya belirsiz içerikleri
ezmez. Dry-run çıktısında patch edilecek her dosya ayrı gösterilir ve apply öncesi backup alınır.

## Davranış değişiklikleri

### Client error support referansı

Fatal island module/chunk/props/mount ve React root hatalarında exception detayı kullanıcıya
gösterilmez. Island alanı şu minimal mesajı gösterir:

```text
Bir sorun oluştu. Referans: client-…
```

Support aynı değeri structured logdaki `errorId` alanıyla arayabilir.

### Structured log korelasyonu

`client runtime error` JSON satırlarında `pageRequestId` her zaman top-level key'dir. SSR document
korelasyonu varsa güvenli request ID değerini, yoksa `null` taşır. Telemetry POST'unun kendi kimliği
ayrı `requestId` alanında kalır.

### Media watch

`server/media.config.json`, `seoAssets`, image, font ve lisans kaynakları `pnpm dev` sırasında
izlenir. Değişiklikler debounce edilir; aynı anda gelen değişiklikler tek takip rebuild'inde
birleştirilir. Config değişince izlenen kaynak listesi de yenilenir.

### Generation-aware dev reload

Development `/readyz` cevabı process başına değişen `x-originloom-dev-generation` header'ı taşır.
Vite, source path'ini tahmin etmek yerine bu değeri izler ve yalnız `tsx watch` gerçekten yeni bir SSR
process'i hazır ettiğinde full document reload gönderir. CSS/client-only değişikliklerde React/Vite HMR
tek başına çalışır. Icon codegen aynı içerikteki TSX/barrel dosyalarını yeniden yazmadığı için no-op
regeneration da server restart'ı başlatmaz.

## Yükseltme

```bash
pnpm up @originloom/tooling@^0.7.18 @originloom/core@^0.7.18 \
  @originloom/react@^0.7.18 @originloom/shared@^0.7.18
pnpm origin:migrate
pnpm origin:migrate --apply
pnpm install
pnpm origin:doctor --strict
pnpm ci
```
