# 0.7.8: consent aracı kendi bloğunu bitirsin

Tür: sıralama hatası düzeltmesi ve bir kararın geri alınması. Kırıcı değişiklik yok.

## Hata: tracking id, aracın iki kaydının arasına giriyordu

0.7.7'de eklenen `awaitDataLayerEvent`, beklediği olayı görünce sıradaki adıma **senkron** geçiyordu:

```js
if (p.event === name) {
  ready();
} // ready() → next() → inline script eklenir → hemen çalışır
```

Bir consent aracı hazır olduğunu tek bir olayla bildirmez. Efilli tek bir senkron blokta iki kayıt
atar:

```js
dataLayer.push({ event: "efilli.consent", categories: {…} });
dataLayer.push({ event: "efilli_essential_granted" });
```

İlk push'un **içinde** devam edildiği için tracking id ikisinin arasına giriyordu:

```
efilli.consent → hkUserTrackingId → efilli_essential_granted → gtm.js   ✗
```

Devam artık `setTimeout(..., 0)` ile erteleniyor; araç bloğunu bitirir, sıra ondan sonra ilerler:

```
efilli.consent → efilli_essential_granted → hkUserTrackingId → gtm.js   ✓
```

`packages/origin-shared/tests/head-scripts.test.ts` bunu doğrular — düzeltme geri alındığında test
düşer.

## Geri alınan karar: consent yoksa GTM de yok

0.7.7 `EFILLI_SCRIPT_URL` tanımlı değilse container'ı hiç yüklemiyordu. Bu geri alındı.

Sebep: bir consent platformu zaten hangi tag'in çalışacağına karar verir; bu kararı bir env
değişkeninin varlığına bağlamak yanlış katmandır. Ve hata biçimi kötüydü — değişken unutulursa ölçüm
**sessizce sıfırlanır**, bu "trafik yok" gibi okunur ve haftalar sonra fark edilir. Tek bir
yapılandırma hatası, teşhisi çok daha zor bir veri kaybına dönüşüyordu.

Artık ikisi bağımsızdır. Production'da `EFILLI_SCRIPT_URL` yoksa başlangıçta bir kez hata log'lanır:

```
EFILLI_SCRIPT_URL is not set — the site is measuring without a consent tool
```

## Yükseltme

Adım yok. 0.7.7'yi kurmuş ve `EFILLI_SCRIPT_URL` vermeden GTM beklediyseniz, container artık
yükleniyor olacak.
