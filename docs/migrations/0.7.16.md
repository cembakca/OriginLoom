# 0.7.16 — SSR kapasite (cache fast-path)

## Özet

Yoğunlukta cache'li sayfaların BYPASS rotalar yüzünden 503 almasını azaltır:

- **Cache HIT/STALE fast-path** — `x-cache: HIT` / `STALE` GET istekleri render admission slot
  almaz; yalnızca MISS/BYPASS/cold-fill render yolu kuyruğa girer.
- **CPU-aware default** — `SSR_MAX_CONCURRENCY` env set değilse `max(32, cores×4)` (üst sınır 256).
  Explicit env her zaman kazanır; mevcut ConfigMap değerleri değişmez.
- **`Retry-After` ince ayarı** — `queue_full` ve `wait_timeout` için reason-bazlı süre.
- **Operasyon runbook** — `ssr_render_rejections_total` troubleshooting (`docs/observability` şablonda).

503 shed davranışı kaldırılmadı; pod koruma mantığı aynı.

## Manuel adım (isteğe bağlı)

Prod'da env ile sabitlediyseniz değişiklik yok. Env yoksa yeni default'u gözden geçirin:

```bash
# Örnek: 8-core pod, env unset → default 32 (floor)
# 16-core pod, env unset → default 64
```

Yoğunlukta 503 görüyorsanız:

1. `/metrics` → `ssr_render_rejections_total{reason=...}`
2. `queue_full` → `SSR_MAX_CONCURRENCY` / `SSR_MAX_QUEUE` veya cache hit oranı
3. Load test stress fazlarında 503 beklenen sinyaldir (`docs/load-testing.md`)
