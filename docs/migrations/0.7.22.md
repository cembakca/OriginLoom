# 0.7.22 — SSR hata referansı ve production kontratları

## SSR hata referansı

`ErrorComponent` artık `{ error, status, errorId }` alır. `errorId`, server'ın aynı hata için
structured log'a yazdığı opaque referanstır; exception mesajı veya stack içermez. Generated boundary
bu değeri `Referans: ...` olarak gösterir. Bilinen generated `server/product/boundary-pages.tsx`
kalıbı `0.7.22-ssr-error-reference` migration'ıyla otomatik güncellenir; özelleştirilmiş boundary'lere
`errorId` gösterimini uygulama sahibi eklemelidir.

Route boundary de hata verirse kullanılan framework-bağımsız son çare 500 sayfası da kendi log
referansını gösterir.

## Production placeholder doğrulaması

Production başlangıcı artık `RELEASE_ID`, `CACHE_PURGE_SECRET`,
`AUTH_REFRESH_COORDINATION_SECRET` ve varsa önceki coordination secret içinde `replace-with-*`,
`change-me`, `changeme`, `placeholder` veya `todo` sentinel'larını reddeder. Kubernetes template'ini
uygulamadan önce bu değerleri deploy sistemi/secret manager ile değiştirin.

## Merkezi cookie güvenlik politikası

`CookieJar`, production'da bütün set, delete ve merge yollarında `Secure` niteliğini merkezi olarak
zorlar. Product middleware'in yanlışlıkla verdiği `secure: false` bu politikayı gevşetemez. Uygulama
kodu için bir migration gerekmez.

## Uygulama

```bash
pnpm origin:migrate
pnpm origin:migrate --apply
pnpm install
pnpm build
```
